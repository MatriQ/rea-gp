# Tool selection, setup, and alternatives

Prepare the smallest tool set that answers the current question. A tool appearing in this list is not a reason to install it. Installing REA does not mean all analysis providers are ready.

## Environment discovery

Run the bundled `scripts/doctor_tools.py` first. By default it discovers executable paths and Python packages; `--probe` runs known version commands. It does not download dependencies, connect devices, or execute the target APK.

```bash
python3 scripts/doctor_tools.py --probe
python3 scripts/doctor_tools.py --probe --require java --require apksigner --require zipalign
python3 scripts/doctor_tools.py --sdk-root SDK_DIRECTORY --ndk-root NDK_DIRECTORY --tool apktool=APKTOOL_JAR
```

Fill path placeholders from the current environment. Repeat `--tool NAME=PATH` as needed. SDK/NDK discovery provides candidates, not compatibility guarantees. The script inventories CLIs and packages in the current Python interpreter; it does not inventory MCP capabilities or other virtual environments. Only missing required tools or failed probes of tools named by `--require` cause failure.

Record selected executable paths, versions, host/device ABI, and supported target formats. Record sources and hashes for downloaded binaries or JARs. Use discovered absolute SDK/NDK paths when they are outside PATH.

## Stages and tools

| Stage | Preferred tools | When needed and alternatives |
| --- | --- | --- |
| ZIP/APK/XAPK inventory and hashes | REA artifact tools; Python standard library | Bundled `inventory_package.py` inventories members, ABI, DEX, resource compression, and nested APKs without Android SDK. It does not parse binary Manifests. |
| Manifest, package name, split declarations | Android SDK `aapt2`; apktool | Use `aapt2 dump badging`/`dump xmltree`; use apktool for full resource editing. Inventory alone does not require decompiling the entire APK. |
| DEX call chains and resource editing | JADX, apktool, smali/baksmali; D8 when needed | JADX output supports understanding and reference tracing, not recompilation as original Java source. APK rebuilding needs a JDK; D8 produces helper DEX from genuine Java source/bytecode. |
| Mono assemblies | REA managed tools, ILSpy/ilspycmd | For rewriting, choose a compatible compiler or Mono.Cecil/dnlib. Verify assembly references, signatures, and Unity APIs. |
| IL2CPP metadata | REA IL2CPP capability; Cpp2IL or Il2CppDumper | Verify metadata/Unity version support. Separate unsupported versions, modified metadata, and mismatched inputs. Repeatedly trying incompatible parsers does not establish evidence. |
| ELF, relocations, and disassembly | NDK `llvm-readelf`, `llvm-objdump`, `llvm-nm`; Ghidra/IDA providers | LLVM is sufficient for function bytes and ELF layout; use analysis databases for complex references, data flow, or pseudocode. Python `pyelftools` and LIEF support structured inspection/rebuilding; independently verify modifications. |
| Branch encoding, instructions, small native helpers | NDK Clang/LLVM; optional Capstone and Keystone | Establish ARM/Thumb/AArch64, endianness, instruction width, PC-relative range, and calling convention. Disassemble generated bytes; assembler success is insufficient. |
| Unity resources | Optional UnityPy, AssetRipper, UABEA | Use when scenes, configuration, Addressables, or bundle contents affect the feature. Preserve source hashes and verify target format support. |
| Resource coverage, downloads, mirrors | Unity resource parsers, target-schema FlatBuffers/JSON parsing, curl/httpx | Map resource keys to objects/files. Preserve dependencies, versions, hashes/CRC, and cache state. Atlas or configuration names do not prove complete content. |
| Optional Firebase and ad changes | JADX/native call analysis, official target SDK documentation, structured XML; bundled patch_manifest.py | Separate subfeatures from shared initialization. Check actual SDK versions, metadata overrides, callbacks, and retries before generating selected changes. |
| Installation and runtime diagnostics | Android SDK `adb`, `emulator`, `avdmanager` | The emulator image must run the target ABI. Building alone needs no device connection. Report verification gaps when an isolated runtime is unavailable. |
| Java/native runtime observation | Frida client/device components; LLDB/lldb-server | Start with logs and an unmodified control. Match Frida core/device versions and ABI; the `frida-tools` package version is not the core version. Match the LLDB device server to the host toolchain. |
| Advanced capture of protected initial values | NDK Clang, target kernel headers, perf/BPF capabilities | Prepare only when ordinary observation cannot resolve the initialization stage. Verify permissions, kernel features, and threading behavior. Do not automatically root the user's device or alter security configuration. |
| Protocol observation and minimal backend | App logs/preserved HAR; optional mitmproxy, Python HTTP framework, SQLite | Observe only the selected test target. Identify HTTP, JNI, Binder, or platform SDK boundaries before selecting a proxy/service. Do not invent responses when TLS traffic cannot be observed. |
| Alignment, signing, delivery | SDK `zipalign`, `apksigner`; JDK `keytool` | Verify each APK separately and sign splits consistently. Changing the ZIP after signing invalidates signatures. |

When REA MCP is unavailable, prefer installed CLIs and their actual `--help`. Node, Java, and .NET are dependencies of particular tools, not universal prerequisites.

## Acquire missing dependencies

- **Reuse installed tools:** Inspect PATH, explicit tool paths, `JAVA_HOME`, `ANDROID_HOME`/`ANDROID_SDK_ROOT`, SDK build-tools, and NDK prebuilt tools. Do not rewrite the user's HOME, global PATH, or MCP registrations to work around a local gap.
- **JARs and standalone binaries:** Obtain a host-compatible version from the project's official releases, place it in the task's `tools/`, and call it by absolute path. Actual release requirements and `--help` take precedence over old command examples.
- **Python:** Install needed packages in a task virtual environment, use that interpreter, and record exact versions. Do not upgrade system Python for one package. Preserve a dependency lock when repeatability matters.
- **SDK/NDK:** Reuse Android Studio or an existing command-line SDK first. Install only selected build-tools, platform-tools, NDK, or emulator images when needed; do not unconditionally install a full IDE.
- **Unsupported parser formats:** Verify original versions and paired package inputs, then choose a build that explicitly supports them. Otherwise use native analysis or controlled runtime observation. Switching tools does not itself recover evidence.
- **Frida/LLDB:** Track device-side location, PID, and ports. Gadget changes the APK and belongs in a separate diagnostic artifact. Use an environment with the required permissions rather than treating physical-device rooting as ordinary setup.
- **Runtime APIs:** Inspect the selected Frida version's module APIs and Java bridge availability. Reading IL2CPP native exports does not require a Java bridge; Android class access uses the bridge mechanism appropriate to that version. Do not assume script API compatibility across releases.
- **Unavailable tools:** Continue independent inventory, static analysis, or build work and identify conclusions still unverified. Do not invent providers, parameters, or successful output.

## Signing order

When the selected tools support these options, use independent task outputs in this order. Supply passwords through controlled files or process environments, not logs or command text.

```bash
zipalign -P 16 -v 4 unsigned.apk aligned.apk
apksigner sign --ks local-signing.jks --out signed.apk aligned.apk
apksigner verify --verbose --print-certs signed.apk
zipalign -c -P 16 -v 4 signed.apk
```

16 KiB ZIP alignment does not replace ELF load-segment checks. Verify file-offset/virtual-address congruence, `p_align`, and the actual target page requirements.

Verify parameters and compatibility against primary sources: [Android zipalign](https://developer.android.com/tools/zipalign), [apksigner](https://developer.android.com/tools/apksigner), [Apktool CLI](https://apktool.org/docs/cli-parameters/), [JADX](https://github.com/skylot/jadx), [Frida Android](https://frida.re/docs/android/), and [Cpp2IL](https://github.com/SamboyCoding/Cpp2IL). Recheck when changing versions; these links are not automatic download instructions.

Additional primary sources: [SDK manager](https://developer.android.com/tools/sdkmanager), [Android NDK](https://developer.android.com/ndk/downloads), [Il2CppDumper](https://github.com/Perfare/Il2CppDumper), [ILSpy](https://github.com/icsharpcode/ILSpy), [Ghidra](https://github.com/NationalSecurityAgency/ghidra), and [UnityPy](https://github.com/K0lb3/UnityPy). Read the applicable requirements and release information when adopting a tool.
